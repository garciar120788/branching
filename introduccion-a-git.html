🐙 Introducción a GitHub

Cómo alojar, compartir y colaborar en tus repositorios de Git

¿Qué es GitHub?

GitHub es una plataforma en la nube para alojar repositorios de Git. Mientras Git corre en tu computadora y guarda el historial de cambios, GitHub te permite subir ese repositorio a internet para respaldarlo, compartirlo y trabajar en equipo con otras personas.

Además de alojar código, GitHub agrega herramientas de colaboración: issues, pull requests, revisiones de código, automatización y más.

Conceptos clave

repositorioTu proyecto alojado en GitHub, con todo su historial de Git
forkUna copia de un repositorio ajeno en tu propia cuenta
pull requestUna propuesta para incorporar tus cambios al repositorio original
issueUn reporte de error o una tarea pendiente sobre el proyecto
cloneDescargar una copia completa de un repositorio a tu computadora

Flujo básico con GitHub

1. Clonar un repositorio existente

git clone https://github.com/usuario/repositorio.git

2. Conectar un repositorio local a GitHub

git remote add origin https://github.com/usuario/repositorio.git
git push -u origin main

3. Subir cambios nuevos

git add .
git commit -m "Descripción del cambio"
git push

4. Traer cambios que otros subieron

git pull

Colaborar con Pull Requests

Un pull request (PR) es la forma en que propones cambios a un proyecto en GitHub:

# 1. Crea una rama para tu cambio
git checkout -b arreglo-bug

# 2. Haz tus cambios y súbelos
git add .
git commit -m "Arreglo el bug X"
git push origin arreglo-bug

Después, desde la página de GitHub, abres un pull request comparando tu rama con main. El equipo puede revisar tu código, comentar y, si todo está bien, aceptarlo (merge) para incorporarlo al proyecto.

Otras cosas útiles en GitHub

📄README.md — la presentación de tu proyecto en la página principal
🐛Issues — para reportar errores o proponer ideas
⚙️GitHub Actions — automatiza pruebas o despliegues cuando subes código
🔒Repositorios privados — visibles solo para ti o tu equipo

Consejo para empezar

Crea una cuenta gratis en github.com, sube un proyecto pequeño con git push y practica abriendo un pull request, aunque sea en un repositorio tuyo. Así entenderás el flujo real que se usa en equipos de trabajo.
